# 06 高风险技术验证方案

## 1. 总体规则

技术验证必须回答“能否稳定达到验收门槛、失败边界在哪里、成本是多少”，不能只证明某个库可以打开文件。

每项试验都要保存：

- 试验版本、代码提交、运行环境和依赖版本。
- 输入样本及 SHA-256。
- 解析器、模型能力槽位、提示版本和渲染器版本。
- 结构化输出、质量结果、耗时、峰值资源和成本。
- 失败样本、错误分类、降级结果和是否可自动恢复。

## 2. SPIKE-01 多格式解析与来源定位

### 2.1 问题

DOCX、PDF、PPTX、XLSX、CSV、TXT 和图片能否在不依赖单一模型的情况下，转化为统一来源块，并保持页、幻灯片、工作表和单元格定位？

### 2.2 处理通道

| 格式 | 结构通道 | 视觉通道 | 合并策略 |
|---|---|---|---|
| DOCX | 段落、样式、表格、关系、页眉页脚 | 渲染页面 | 结构为主，视觉补充分页/图形 |
| PDF | 文本块、字体、页面、表格 | 页面图片+OCR/视觉 | 原生文字优先，扫描页走 OCR |
| PPTX | 文字、备注、图形树、母版、关系 | 幻灯片渲染 | 结构与视觉必须同时保留 |
| XLSX | 工作表、单元格、公式、合并、表区、图表元数据 | 工作表预览 | 结构负责数据，视觉负责表头/版式判断 |
| 图片 | EXIF/尺寸 | OCR+视觉 | 保留坐标和置信度 |
| 旧 Office | 隔离转换为标准格式 | 转换后渲染 | 不执行宏，不直接解析未知二进制对象 |

### 2.3 试验步骤

1. 使用 BM-02、05、08、12、13、15 的冻结输入。
2. 验证 magic bytes、大小、页数/表数和加密状态。
3. 各格式进入专用解析器，输出 `source_blocks`。
4. 生成页面/幻灯片/工作表缩略图并运行视觉补充。
5. 合并结构与视觉结果，禁止视觉模型覆盖确定性单元格值。
6. 对关键事实、表格、图片和模板元素执行来源定位回放。
7. 注入损坏、加密、超大图片、复杂合并单元格和扫描页。

### 2.4 通过条件

- 所有支持格式正常样本产生有效来源块。
- 基准关键事实解析召回率不低于 95%。
- 关键来源定位正确率 100%。
- XLSX 关键值和公式原样读取率 100%。
- PPTX 页面文字、备注和图形关联覆盖率不低于 98%。
- 模板示例文字进入项目事实的数量为 0。
- 单文件失败不阻断其他文件；部分失败能说明范围和影响。

### 2.5 失败退出

若 PPT/XLSX/扫描件任一核心通道达不到门槛，不进入全部格式开发。先缩小支持范围或更换解析组合，禁止用“让一个通用模型直接看全部文件”绕过定位和确定性检查。

## 3. SPIKE-02 长文档连续生成

### 3.1 问题

在模型上下文有限的情况下，能否生成 2 万字以上解决方案，并在中断、修改和追加材料后保持结构、术语、数字和来源一致？

### 3.2 原型组件

- 项目模型快照。
- 术语表、数字注册表、假设注册表和写作风格。
- 文档目录与章节合同。
- 语义小节任务。
- 章节正文、摘要、声明、引用、内容哈希和剩余计划。
- 独立审核能力槽位。

### 3.3 试验组

| 组 | 方法 | 目的 |
|---|---|---|
| A | 单次长提示直接生成 | 作为失败/成本对照，不作为候选架构 |
| B | 按章生成，只携带前文全文 | 测试上下文膨胀 |
| C | 项目模型+章节合同+相关摘要 | 目标方案 |
| D | C + 生成后独立审核与局部修复 | 目标生产方案 |

使用 BM-12、14、15、17、18；每项至少执行三次，并在 30%、60%、90% 处注入 Worker 中断。

### 3.4 检查

- 标题、目录、章节目标和必引对象完整性。
- 术语变体、关键数字、范围、不包含内容和假设一致。
- 重复段落、跨章矛盾、无来源关键事实和遗漏对象。
- 中断恢复后内容重复、断裂和计划丢失。
- 修改单条需求后受影响章节召回和无关变化。

### 3.5 通过条件

- 2 万字以上文档完整生成率 100%。
- 中断恢复成功率 100%，不出现重复章节或盲目续写。
- 关键数字和术语一致率 100%。
- 关键事实来源覆盖达到 100%；无来源且未标记关键事实为 0。
- 受影响章节召回不低于 95%，无关段落变化低于 2%。
- 相比“携带前文全文”，目标方案的上下文增长受控且成本可解释。

## 4. SPIKE-03 企业模板与 Office/PDF 生成

### 4.1 问题

能否识别用户提供的空白或含示例内容的 Word、Excel、PPT 模板，并生成可编辑、可打印、可转换 PDF 的成果？

### 4.2 模板契约

模板解析后生成 `template_profile`：

- 品牌：Logo、颜色、字体和图片风格。
- Word：纸张、页边距、标题样式、正文、表格、页眉页脚、封面。
- Excel：工作表角色、表头、输入/公式样式、打印区域、冻结和数据验证。
- PPT：母版、版式、安全区、标题/正文占位符、页脚和页面比例。
- 风险：字体缺失、母版损坏、宏、外链、嵌入对象、示例文字和不可编辑内容。

### 4.3 试验步骤

1. 使用 BM-10、15、17 的平台模板和企业模板。
2. 模板分类与内容材料完全分离。
3. 生成相同内容版本的默认模板和企业模板渲染版本。
4. 打开 DOCX/XLSX/PPTX，检查结构和可编辑性。
5. 转换 PDF 并逐页渲染视觉检查。
6. 测试字体缺失、模板损坏、极端标题、长表格和大段文字。
7. 测试企业模板失败后回退默认模板，不重跑内容生成。

### 4.4 通过条件

- 核心 Office 文件打开率 100%。
- 企业模板成功识别率不低于 95%；不能识别时明确降级。
- 模板示例内容泄漏为 0。
- PPTX 文字、表格和基础图形原生可编辑。
- Excel 公式、输入格和计算格区分明确，公式检查 100% 通过。
- DOCX/PDF 无严重分页、溢出、重叠和截断。
- 更换模板只产生渲染版本，不增加模型调用。

## 5. SPIKE-04 七类成果一致性与局部修改

### 5.1 问题

七类成果能否从统一项目模型生成并在修改后保持数字、范围、术语和依赖一致，而不重跑整个项目？

### 5.2 试验修改集

每个 BM-01、05、12、15、17、18 至少执行：

1. R：替换 Logo 和 PPT 模板。
2. C：修改角色日单价和税率。
3. S：修改一条关键需求。
4. S：追加一个外部接口。
5. S：锁定需求后上传冲突材料。
6. P：改变产品形态或核心范围。
7. 回退到上一发布内容版本。

### 5.3 通过条件

- 关键数字跨成果一致率 100%。
- 需求—功能—估算追踪覆盖 100%。
- 客户包内部成本泄漏为 0。
- R 类修改模型调用为 0。
- C 类修改仅执行规则计算和相关渲染。
- S 类受影响对象召回不低于 95%，无关变化低于 2%。
- P 类形成候选项目模型，失败时旧发布版继续可用。
- 单成果失败不重跑无关成果。

## 6. SPIKE-05 安全、隔离与删除

虽然不属于文件/模型能力验证，但外部开放前必须单独完成。

### 6.1 场景

- 修改项目 ID、成果 ID、文件 ID 和签名下载地址尝试跨用户读取。
- 恶意文件名、伪造 MIME、路径穿越、压缩炸弹和超大图片。
- 文档内提示词注入、外链和宏。
- 删除过程中继续读取、下载和启动修改。
- 备份恢复后已删除项目重新出现。
- 日志、告警和运行后台泄漏正文或手机号。

### 6.2 通过条件

- 跨项目访问成功次数为 0。
- 删除请求后普通访问立即失效。
- 恢复备份后删除墓碑正确重放。
- 生产后台默认不可查看正文。
- 恶意内容不能改变工具权限或触发外部动作。

## 7. 试验顺序与退出门

```text
SPIKE-01 多格式来源块
   ↓
SPIKE-02 长文档连续性 ─┐
SPIKE-03 Office/模板 ──┼→ SPIKE-04 七成果一致性与修改
                        └→ SPIKE-05 安全与删除
```

SPIKE-01 是后续全部验证的前提。SPIKE-02 与 SPIKE-03 可并行。SPIKE-04 通过后才能开始正式成果工作台实施；SPIKE-05 通过后才能对外开放。

## 8. 试验报告模板

每项结论必须分为：

- 已证明能力。
- 未达到门槛的样本。
- 自动降级与恢复行为。
- 仍需测试的边界。
- P50/P95 时间和成本。
- 对产品范围、数据契约和实施路线的影响。
- 继续、限制范围、替换方案或停止的决策。
