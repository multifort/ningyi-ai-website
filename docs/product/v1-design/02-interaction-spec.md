# 02 页面与交互规格

## 1. 用户可见主流程

```text
官网产品入口
  → 填写最少信息 / 选择材料与模板
  → 点击“开始生成方案”
  → 用户名密码登录或注册（保持输入与文件）
  → 上传与快速理解
  → 项目理解（非强制确认门）
  → 七类成果渐进生成
  → 成果工作台查看、修改、导出
  → 我的方案 / 数据管理
```

系统内部可以创建 `project` 和 `run`，但界面不得要求用户先执行“新建项目”“创建任务”或“选择模型”。

## 2. 页面信息架构

| 页面 | 主要任务 | 主要对象 | 关键动作 |
|---|---|---|---|
| 官网产品入口 | 说明产品价值并让用户立即输入 | Intake 草稿、待上传文件 | 填写、选择、开始 |
| 方案操作台 | 完善信息、分类材料与模板 | Intake、上传批次 | 编辑、上传、移除、重试 |
| 项目理解 | 展示系统理解和不确定项 | 项目快照、来源、冲突 | 锁定、纠正、方向选择 |
| 成果工作台 | 查看七类成果与状态 | 成果、版本、来源、影响 | 修改、局部重生成、导出 |
| 我的方案 | 查看历史与继续处理 | 项目摘要、运行状态 | 打开、下载、删除 |
| 数据管理 | 查看留存和删除状态 | 文件、项目、删除任务 | 删除、注销、查看状态 |

## 3. 官网产品入口

### 3.1 首屏结构

首屏同时承担价值说明和真实输入，不使用“点击后再进入多步表单”的纯宣传结构。入口对用户显示“说清楚你要解决的问题，剩下的交给我们”，不显示“需求画布”“项目任务”等内部产品术语。

1. 标题与一句话价值：从现有材料直接形成可交付的需求、方案、估算、报价、计划和汇报成果。
2. 方案用途：主要用途必选；次要用途可多选。
3. 面向谁：组织名称、行业、组织类型、实际用户，允许选择“暂不确定”。
4. 需要解决什么：需求描述文本区和内容材料选择区至少完成一种。
5. 希望做成什么：Web、小程序、App、管理端、看板、系统集成、AI Agent、暂不确定。
6. 约束折叠区：预算、周期、部署、接口、迁移、安全与合规，全部可选。
7. 已有材料和模板：内容材料、企业模板、Logo/品牌素材三个独立区域。
8. 主按钮：“开始生成方案”。

### 3.2 字段规则

| 字段 | 类型 | 必填 | 默认与校验 |
|---|---|---:|---|
| 主要用途 | 单选 | 是 | 客户沟通、内部立项、售前方案、估算报价、实施规划、汇报演示、其他 |
| 次要用途 | 多选 | 否 | 不影响最低条件 |
| 组织名称 | 文本 | 否 | 最长 120 字；可后补 |
| 行业 | 可搜索单选 | 否 | 可选择其他/暂不确定 |
| 组织类型 | 单选 | 否 | 企业、政府/事业单位、社会组织、个人团队、暂不确定 |
| 实际用户 | 标签+文本 | 否 | 可选择暂不确定 |
| 需求描述 | 多行文本 | 条件必填 | 与有效内容材料至少满足一种；最长值配置化 |
| 产品形态 | 多选 | 否 | 包含 AI Agent 和暂不确定 |
| 预算/周期 | 区间 | 否 | 允许未知，不阻断 |
| 部署/接口/迁移/安全 | 折叠字段组 | 否 | 默认未提供，不默认推断为“无” |

### 3.3 登录前草稿

- 文本和选择项保存在浏览器草稿，并生成随机 `draft_id`。
- 文件仅保留浏览器 `File` 引用和本地展示信息，登录前不应写入公开目录。
- 点击主按钮后验证最低条件；通过后弹出产品账号登录，可在同一弹层切换注册。
- 登录成功后创建产品用户 Session，把 `draft_id` 绑定到用户，上传文件并创建内部项目。
- 登录或注册失败时，弹窗保留当前字段和文件选择。
- 用户主动刷新导致浏览器无法恢复文件引用时，保留文字字段并明确要求重新选择文件，不伪装已上传。

## 4. 上传交互

### 4.1 分类区域

| 区域 | 解释 | 允许行为 |
|---|---|---|
| 项目内容材料 | 需求、纪要、历史方案、功能表、截图等 | 参与事实与需求提取 |
| 企业模板 | 空白或示例 Word/Excel/PPT 模板 | 仅提取样式、母版、版式和占位符 |
| 品牌素材 | Logo、品牌色、字体说明和图片素材 | 只用于渲染和品牌配置 |

### 4.2 文件状态

`已选择 → 校验中 → 等待上传 → 上传中 → 已上传 → 解析中 → 已解析`

异常分支：

- `类型不支持`：给出可执行建议，如转换为 PDF。
- `需要密码`：要求上传未加密版本、删除或保留但忽略。
- `部分解析失败`：展示失败范围和可能影响，允许替换、忽略并继续或上传 PDF 版本。
- `疑似损坏`：不进入解析 Worker，允许删除或重新选择。
- `模板不可用`：允许改用默认模板或上传其他模板；不阻断内容生成。

### 4.3 进度表达

- 上传进度与解析进度分开显示。
- 不显示虚假的单一百分比；以文件级状态和总体已完成数量为主。
- 用户可在后台继续处理时离开页面，通过“我的方案”返回。
- 在项目理解或成果形成后补充内容材料时，系统会先把当前理解和成果标记为“材料已更新”，等待该批文件全部上传后重新解析；新材料不会静默混入既有版本。

## 5. 项目理解页面

### 5.1 页面结构

1. 顶部：项目名称建议、当前阶段和自动保存状态。
2. 左侧/主区：客户与用户、项目目标、范围、产品形态、8—12 条核心需求、关键约束。
3. 右侧：材料处理状态、来源、冲突、系统假设和待用户方向选择。
4. 底部：系统正在继续生成的状态，不设置“全部确认后才开始”。

### 5.2 信息状态

| 状态 | 含义 | UI |
|---|---|---|
| 用户已确认 | 用户输入、修改或锁定 | 实色标记，可解锁 |
| 材料一致 | 多个有效来源一致 | 来源数量和定位 |
| 单一来源 | 仅一处材料支持 | 中性提示，不阻断 |
| 系统建议 | 基于证据的可替换建议 | “建议”标记 |
| 材料冲突 | 两个高优先级来源冲突 | 展示差异并要求方向选择 |
| 未提供 | 无证据且不应猜测 | 明确显示“未提供” |

### 5.3 用户操作

- 编辑字段：生成用户确认事实并记录原值。
- 锁定字段：后续新增材料不能静默覆盖。
- 查看来源：打开文件定位信息和摘录，不必下载原文件。
- 选择方向：一次最多展示三个真正影响方向的问题。
- 暂不确定：形成显式假设，系统继续生成并标注影响。

## 6. 成果工作台

### 6.1 桌面端框架

- 左栏：七类成果、完成状态、质量状态和版本。
- 中栏：当前成果的结构化视图或连续阅读视图。
- 右栏：选中对象的来源、关联、影响、锁定和历史。
- 顶栏：项目状态、自动保存、内容版本、模板、导出与更多操作。

### 6.2 成果状态

`等待依赖 → 生成中 → 候选检查 → 可查看 → 部分受影响 → 重新生成中 → 已发布 → 失败`

“可查看”表示候选版本通过该成果最低质量门；“已发布”表示成为默认下载版本。失败成果必须标出受影响范围，其他可用成果继续开放。

### 6.3 修改入口

| 类型 | 典型操作 | 系统行为 |
|---|---|---|
| R 仅渲染 | 更换 Logo、颜色、模板 | 只生成新渲染版本 |
| C 重新计算 | 修改税率、日单价、角色参数 | 程序计算并更新引用摘要 |
| S 局部语义 | 修改需求、功能、部署或计划 | 关系图确定受影响对象并局部重生成 |
| P 项目重构 | 修改客户、产品方向或核心范围 | 建立新正式项目模型候选版本 |

每次修改先展示影响摘要；用户提交后立即保存操作记录，候选版本检查失败时保留旧发布版。

### 6.4 导出

- 可导出单个成果的可用格式。
- 可生成客户交付包、内部评审包和完整归档包。
- 包类型只改变可见范围、渲染选择和文件组合，不触发内容模型重新生成。
- 导出任务显示组装、渲染、检查、可下载或失败状态。

## 7. 我的方案

列表卡片包含：项目名称、客户简称、项目类型、当前阶段、已完成成果数量、最近更新时间、内容版本和异常提示。

允许操作：打开、继续处理、下载最近发布包、删除。页面不出现“新建空白项目”，主创建入口仍是官网需求画布。

## 8. 数据管理与删除

删除分两步：

1. 用户确认删除范围并完成当前密码二次确认（后续接入短信/邮箱验证码时保持同一接口语义）。
2. 项目立即进入 `deletion_pending`，所有普通读取和下载失效；后台异步清理并展示状态。

删除状态：`等待清理 → 清理中 → 已删除`；失败时系统自动重试并记录匿名错误，不要求人工处理正文。

注销账号前必须展示现有项目及删除影响。账号删除与项目数据删除使用同一可审计任务链路。

## 9. 移动端最低范围

- 完成结构化输入、文件选择、验证码登录和上传状态查看。
- 查看项目理解、冲突和方向选择。
- 查看成果状态和移动版预览。
- 下载单文件或成果包。
- 删除项目和查看删除状态。

复杂表格修改、PPT 页面编辑和多对象影响对比可提示使用桌面端，但不得阻止项目启动或结果获取。

## 10. 全局异常原则

- 错误必须说明“发生了什么、影响什么、系统会做什么、用户可以做什么”。
- 不使用“未知错误，请联系人工客服”作为唯一恢复路径。
- 自动重试期间展示下一步和旧版可用性。
- 单个文件、章节、页面或公式失败时缩小失败范围，不把整个项目重置为失败。
- 用户离开页面不取消后台任务，除非明确点击停止或删除。
