# 07 模型能力槽位、质量评测与成本控制

## 1. 原则

- 业务代码引用能力槽位，不引用具体模型名称。
- 免费/快速理解阶段优先低成本；正式分析和复杂生成优先质量。
- 正式项目模型不得直接继承快速模型的隐蔽自由文本结论。
- OCR、视觉、长文档、审核和 Office 渲染不是一个模型的单一任务。
- 成本优化不能降低正式分析门槛，优先减少重复调用、缩小上下文和使用程序计算。

## 2. 能力槽位

| 槽位 | 任务 | 质量优先级 | 成本策略 |
|---|---|---:|---|
| FAST_ANALYSIS_MODEL | 文件分类、快速摘要、初步字段、冲突候选 | 中 | 低成本、短输出、严格上限 |
| FORMAL_ANALYSIS_MODEL | 正式项目模型、需求归并、复杂判断 | 最高 | 高质量；按业务域分批 |
| DOCUMENT_MODEL | 章节合同和长文档语义小节 | 高 | 只传项目模型和相关摘要 |
| REVIEW_MODEL | 独立语义审核、遗漏、矛盾和无来源结论 | 高 | 只审受影响范围；与生成上下文隔离 |
| VISION_MODEL | 页面、截图、图形、流程和版式理解 | 高 | 仅视觉必要页面；先结构解析 |
| OCR_ENGINE | 扫描件与图片文字/坐标识别 | 高 | 本地/服务能力可替换，按页计量 |
| EMBEDDING_MODEL | 项目内检索和相关章节选择 | 中 | 严格项目隔离；不跨项目缓存 |
| OPTIONAL_TRANSLATION_MODEL | 非中文材料标准化 | 中 | V1 非核心；仅必要段落 |

渲染器、公式引擎和 ZIP 组装不是模型槽位。

## 3. 模型注册表

每个槽位可以配置多个候选，注册表包含：

- `provider`、`model_id`、`model_version`。
- 支持输入类型和上下文上限。
- 结构化输出能力和最大输出。
- 数据区域、保留和供应商安全配置。
- 输入/输出/缓存/图片/OCR 单价及币种、生效时间。
- 并发、速率限制和超时。
- 已通过的基准项目与最低版本。
- 允许环境：development、benchmark、canary、production。
- 降级链和禁止任务。

价格与能力可能变化，必须通过配置和供应商账单校准，不写入业务代码或长期文档常量。

## 4. 评测数据集

### 4.1 快速理解

从 18 个基准项目提取：文件分类、用途、客户/用户、初步目标、核心需求候选、明显冲突和是否可继续。评分重点为速度、成本、关键字段召回和错误自信。

### 4.2 正式分析

评分：

- 关键事实召回与错误事实。
- 需求归并、重复消除和验收标准。
- 功能覆盖、边界、接口和非功能要求。
- 冲突、假设和不包含内容。
- 来源引用正确性。
- AI Agent 任务、知识、工具、权限、记忆、评测与失败降级完整性。

### 4.3 长文档

评分：章节合同遵守、术语、数字、来源、跨章一致、重复、可读性、中断续跑和局部修改稳定性。

### 4.4 审核

使用预埋错误集评测审核召回：数字冲突、术语变体、无来源事实、范围越界、遗漏章节、重复段落和内部信息泄漏。审核模型自身不得直接修改确定性数据。

### 4.5 视觉

评测图片/页面中的流程、界面、表格关系、图表含义和模板元素分类。视觉结果必须链接到页面与坐标。

## 5. 评测方式

每个候选至少运行目标基准子集三次，记录平均值和离散性。自动评分与研发期人工黄金评审结合；人工评审只建立基准，不进入生产用户项目处理。

| 指标 | 定义 |
|---|---|
| Fact Recall | 期望关键事实被正确表达的比例 |
| Unsupported Fact Rate | 无来源且未标记假设的关键事实比例 |
| Relation Coverage | 期望需求—功能—估算等关系覆盖 |
| Structured Validity | JSON Schema 和业务规则一次通过比例 |
| Review Recall | 预埋错误被识别比例 |
| Stability | 同输入多次运行的关键对象一致性 |
| Latency | P50/P95 端到端及分阶段时间 |
| Cost | 单项目、阶段、成果和成功交付成本 |

任何存在严重安全边界问题或高 Unsupported Fact Rate 的模型，不因价格低而进入生产槽位。

## 6. 路由规则

### 6.1 快速理解

- 先运行确定性文件元数据和结构抽取。
- 低成本模型只处理压缩后的代表内容和结构摘要。
- 输出严格 JSON，最多展示 8—12 条核心需求候选。
- 失败时可切备用低成本模型或延迟显示，不阻断已登录后的正式处理。

### 6.2 正式分析

- 按业务域和对象类型分批，不把全部材料塞入单次上下文。
- 关键证据通过来源块检索选择；用户锁定信息始终注入。
- 项目模型候选必须通过 Schema、关系和证据检查。
- 复杂或冲突对象可升级到更强候选，正常对象不升级。

### 6.3 长文档

- 每次只生成一个语义小节。
- 上下文包含章节合同、必引对象、文档基线、相关章节摘要和剩余计划。
- 已完成全文不重复携带。
- 审核只检查新小节及相关全局注册表。

### 6.4 修改

- R 类模型调用为零。
- C 类模型调用通常为零。
- S 类只重跑影响图覆盖对象和相关章节。
- P 类才重建正式项目模型。

## 7. 成本台账

每次能力调用记录：

- 匿名项目/运行/任务 ID。
- 槽位、供应商、模型版本和提示版本。
- 输入/输出/缓存 Token、图片页数、OCR 页数。
- 供应商报价版本、估算成本和账单校准成本。
- 成功/失败、重试、降级和失败原因。
- 产生的对象、章节或质量结果。

项目成本拆分为：文件验证、解析/OCR、快速理解、正式项目模型、七类成果语义、审核、Office/PDF 渲染、存储/下载、重试与自动修复。

## 8. 优先优化顺序

1. 杜绝多成果重复读取原始材料和重复生成相同内容。
2. 程序承担公式、汇总、编号、版本、渲染和打包。
3. 长文档只携带相关上下文与摘要。
4. 修改按影响图局部执行。
5. 缓存确定性解析和同版本渲染结果。
6. 低风险对象使用合格的较低成本正式候选。
7. 最后才考虑降低正式质量槽位。

## 9. 降级策略

| 失败 | 自动动作 | 禁止行为 |
|---|---|---|
| 快速模型超时 | 备用低成本候选或跳过预览继续正式阶段 | 使用空结果冒充项目理解 |
| 正式模型结构无效 | 同模型结构修复一次，再切备用正式候选 | 直接发布未校验自由文本 |
| 视觉失败 | 缩小页面、降低分辨率或备用视觉候选 | 覆盖结构解析的确定性数据 |
| 审核失败 | 保留候选、重试或切审核候选 | 未检查即发布 |
| 供应商不可用 | 按已验证降级链切换 | 使用未跑基准的模型进入生产 |

## 10. 上线门槛

- 每个生产槽位至少有一个通过目标基准集的主候选。
- FORMAL、DOCUMENT、REVIEW 至少各有一个已验证备用候选或明确的暂停策略。
- 价格、上下文、超时和并发均配置化。
- 质量退化自动触发回退，不只看供应商 HTTP 成功率。
- 生产路由变更经过基准 → canary → 小流量 → 全量步骤。
