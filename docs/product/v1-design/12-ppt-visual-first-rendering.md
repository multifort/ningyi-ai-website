# 12 PPT 视觉优先生成与无损复原

## 1. 状态与目标

当前已完成“原生图形化第一阶段”：在现有确定性 PPT 渲染器中，按章节类型将已校验文字映射为可编辑的内容卡片、实施时间线、风险矩阵和工作量指标卡片。该阶段不调用图像模型，不改写事实，不替代完整 M9。

完整视觉优先专项仍在主流程 M8 验收后实施。目标不是把生成图片直接贴进 PPT，而是在保持内容完整、格式统一和原生可编辑的前提下，提高整套汇报材料的视觉与内容编排质量。

固定链路：

```text
统一项目模型 / Deck / Slide
            ↓ 锁定内容与校验清单
       页面视觉参考图
            ↓ 仅提取视觉意图
       语义化 HTML 页面
            ↓ 对象级映射
       原生可编辑 PPTX
            ↓ 回渲染与核对
        可发布成果版本
```

## 2. 核心原则

1. **内容唯一事实源**：正文、数字、表格、图表数据、引用和备注只来自 `Deck`、`Slide`、`VisualBlock` 及统一项目模型。
2. **图片只负责视觉**：生成图片用于确定构图、层级、氛围和图形语言，禁止从图片 OCR 恢复正式内容。
3. **HTML 负责结构化复原**：每个可编辑元素必须具有稳定 `slide_id`、`content_id`、语义类型和布局约束。
4. **PPT 负责原生交付**：文字、基础形状、表格和支持范围内的图表转换为原生对象；复杂装饰图可作为独立图片层。
5. **全套格式统一**：Deck 级设计令牌优先于单页视觉参考，任何页面不得自行产生第二套字体、色板或间距规则。

## 3. 分阶段流程

### 3.1 内容锁定

- 生成逐页内容清单，包含标题、正文块、数字、表格单元格、图表数据、引用、备注和来源标识。
- 为每个内容块分配稳定 `content_id`，计算规范化文本与数据摘要。
- 视觉生成前先完成事实、数字、来源和页面目的质量门；视觉阶段不得改写事实内容。

### 3.2 视觉参考生成

- 先确定 Deck 级视觉方向：色板、字体层级、网格、留白、图形语言、图片处理和页面版式族。
- 按页面目的生成参考图，可使用占位符表达文字区域，避免让图片模型承担精确中文排版。
- 封面、章节页、架构页、数据页等使用受控版式族，禁止每页独立随机探索。
- 视觉参考与提示词、模型、种子（供应商支持时）、尺寸和风格版本一并存档。

### 3.3 HTML 语义复原

- 按参考图重建布局，但正文从内容清单注入，而不是从图片识别。
- DOM 元素必须标注对象类型与 `content_id`，并使用共享 CSS 设计令牌。
- HTML 使用固定画布比例、安全区和字体回退规则；溢出时回到布局策略处理，不截断正文。
- 图表使用结构化数据渲染，表格保持行列关系和单元格语义。

### 3.4 PPT 原生对象映射

| HTML/语义对象 | PPTX 目标 | 编辑要求 |
|---|---|---|
| 标题、正文、标签 | 文本框 | 字体、字号、颜色、行距可编辑 |
| 容器、线条、强调块 | 原生形状 | 填充、描边、尺寸可编辑 |
| 表格 | 原生表格 | 单元格内容与样式可编辑 |
| 支持范围内的图表 | 原生图表或结构化图形组 | 数据或组件可编辑 |
| Logo、照片、复杂插图 | 独立图片层 | 可替换、裁切和移动 |
| 背景装饰 | 母版或独立背景层 | 不遮挡正文，不承载事实内容 |

不支持可靠原生映射的复杂视觉必须标记为“装饰性不可编辑资产”，不能将整页扁平化为一张图片冒充可编辑 PPT。

### 3.5 回渲染与发布

- 将 PPTX 渲染为逐页图片，与 HTML 版本做几何、颜色和文本区域比对。
- 从 PPTX 重新提取文字、表格、图表数据和备注，与内容清单逐项核对。
- 任何内容缺失、关键数字变化、引用丢失、样式漂移或文件损坏都阻断发布。
- 候选失败时保留上一可用发布版，并记录失败阶段和可重试范围。

## 4. 无损与一致性验收

| 维度 | 发布要求 |
|---|---|
| 必需正文 | `content_id` 覆盖和规范化文本一致率 100% |
| 数字与表格 | 关键数字、币种、单位、表格单元格一致率 100% |
| 引用与备注 | 必需引用和演讲备注保留率 100% |
| 可编辑性 | 文字、基础形状、表格和支持图表均为原生对象 |
| 页面完整性 | 无截断、重叠、越界、空白异常和模板占位内容 |
| 格式一致性 | 字体、色板、网格、间距、圆角、描边、图标与图片规则来自同一令牌版本 |
| 视觉还原 | PPTX 回渲染结果通过按页面类型配置的视觉差异门槛 |
| 文件有效性 | PPTX 可打开、可保存、页数正确，PDF 导出关键内容一致 |

## 5. 成本与修改策略

- 视觉参考按 `页面目的 + 内容结构摘要 + 设计令牌版本` 缓存，可复用时不再次调用图像模型。
- 纯正文或数字修改优先更新 HTML/PPT 对象；未改变构图意图时不重新生成图片。
- 仅对视觉差异超限或布局结构变化的页面局部重建，不整套重复生成。
- 图像模型、HTML 复原和 PPT 渲染分别记录耗时、调用成本、成功率和重试次数。

## 6. 开发边界

- 第一阶段已修改现有 PPT 生成器，范围仅限于原生文字、基础形状和结构化内容的确定性排版；复杂装饰图、图片模型和 HTML 复原仍不在当前实现内。
- M8 前继续使用现有可验证链路，保证七类成果主流程和无人值守能力优先完成。
- M9 先以 3 种典型页面（封面、方案架构、数据/报价）做技术验证，再扩展至完整 Deck。
- 企业 PPT 模板继续作为可选输入；模板母版、字体和品牌规则必须转换为同一套 Deck 设计令牌。
