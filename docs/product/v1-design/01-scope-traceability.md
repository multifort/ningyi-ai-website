# 01 V1 范围与需求追踪

## 1. 产品边界

V1 是“企业软件与 AI Agent 项目方案自动交付产品”，不是聊天机器人，也不是项目管理工具。用户在官网产品入口直接填写结构化信息并选择材料；登录后系统继续处理，不要求用户新建项目、创建任务或选择模型。

### 1.1 成功定义

一个标准项目能够在没有人工处理用户项目的情况下，从多格式输入稳定形成七类一致、可追溯、可修改、可下载、可删除的成果，并通过自动质量门。

### 1.2 V1 非目标

- 支付、订单、套餐、发票、优惠、退款和修改计费。
- 完整在线 Word、Excel、PowerPoint 编辑器。
- 多成员组织、审批流和团队协作权限。
- 通用项目管理、任意 Agent 编排或提示词市场。
- 医疗、金融交易、工业控制等安全关键专业结论。
- CAD、BIM、硬件、固件和专业工程设计。
- 以人工分析、人工改稿或人工交付作为正常处理节点。

## 2. 需求追踪矩阵

| 编号 | 需求 | V1 验收证据 | 优先级 |
|---|---|---|---|
| REQ-001 | 官网首屏提供真实结构化输入和材料选择入口 | 未登录用户可以填写、选择文件并触发开始 | P0 |
| REQ-002 | 登录前输入状态与文件选择不得丢失 | 用户名密码登录或注册后恢复同一 Intake 草稿并继续上传 | P0 |
| REQ-003 | 登录后不要求新建项目、任务或选择模型 | 登录成功直接进入当前处理状态或项目理解页 | P0 |
| REQ-004 | 入口最低条件仅为方案用途，以及需求描述或有效材料至少一种 | 自动化用例覆盖所有阻断与非阻断组合 | P0 |
| REQ-005 | 支持 DOCX、PDF、PPTX、XLSX、CSV、TXT、PNG、JPG、JPEG、WebP | 基准材料解析成功并产生来源块 | P0 |
| REQ-006 | 内容材料、企业模板与品牌素材分区上传 | 三类材料分类明确，不将模板示例文字当作需求事实 | P0 |
| REQ-007 | 快速理解使用低成本能力，正式分析重新基于原始证据构建项目模型 | 运行记录显示两个独立阶段及能力槽位 | P0 |
| REQ-008 | 项目理解展示客户、用户、目标、范围、需求、冲突、假设和来源 | 用户可查看并锁定字段；只有方向问题需要选择 | P0 |
| REQ-009 | 七类成果共享统一项目模型 | 跨成果关键数字、范围、术语和编号一致 | P0 |
| REQ-010 | 七类成果按依赖关系渐进完成 | 用户可查看已完成成果，单个失败不阻塞无依赖成果 | P0 |
| REQ-011 | 成果支持来源追溯和影响查看 | 从需求/数字可定位文件、页/幻灯片/工作表/单元格 | P0 |
| REQ-012 | 支持结构化修改、锁定、追加材料、局部重生成和版本回退 | 修改只影响关系图覆盖对象，无关变化率达标 | P0 |
| REQ-013 | 支持用户企业 Word、Excel、PPT 模板 | 三类模板可识别、验证、渲染和失败降级 | P0 |
| REQ-014 | 支持 DOCX、XLSX、PPTX、PDF 和 ZIP 输出 | 文件可打开、可编辑、无严重排版错误 | P0 |
| REQ-015 | 客户包、内部包、完整归档包不重复生成内容 | 同一内容版本产生不同可见范围与物理文件组合 | P0 |
| REQ-016 | 长文档可分节生成、中断续跑和全局检查 | 2 万字以上文档在中断后继续且术语/数字一致 | P0 |
| REQ-017 | 用户可查看历史方案但无需“新建空白项目” | 我的方案展示状态、版本、更新时间和操作 | P1 |
| REQ-018 | 用户可删除方案并查看删除状态 | 删除后立即禁止访问，后台完成级联清理 | P0 |
| REQ-019 | AI Agent 作为正式项目类别和基准项目 | 项目模型包含任务、知识、工具、权限、记忆、评测和成本 | P0 |
| REQ-020 | 正式运行无人值守 | 30 次连续运行不需要人工处理用户项目 | P0 |

## 3. 非功能需求

| 编号 | 要求 | 验收口径 |
|---|---|---|
| NFR-001 | 幂等 | 同一任务重复消费不产生重复版本、重复扣量或冲突文件 |
| NFR-002 | 可恢复 | Worker 中断后从未完成语义单元或渲染单元继续 |
| NFR-003 | 可观测 | 每阶段记录匿名执行 ID、耗时、能力槽位、用量、错误码和重试原因 |
| NFR-004 | 可解释成本 | 按项目、阶段、成果和重试记录模型/OCR/渲染成本 |
| NFR-005 | 可配置 | 模型、解析器、阈值、留存期和并发不写死在业务逻辑 |
| NFR-006 | 可回退 | 候选内容或渲染失败时，最近已发布版本保持可用 |
| NFR-007 | 无关变化受控 | 局部修改后无关对象变化率低于 2% |
| NFR-008 | 文件质量 | 核心 Office/PDF 打开率 100%，严重截断、重叠和公式错误为 0 |
| NFR-009 | 数据一致 | 关键数字及跨成果确定性字段一致率 100% |
| NFR-010 | 移动可用 | 手机端可完成输入、上传、登录、查看状态、预览和下载 |
| NFR-011 | ToC 并行执行 | 不得以全局单任务串行队列作为正式运行形态；不同用户、同一用户的不同方案可并行，只有同一方案内存在数据依赖的步骤串行。正常容量下任务排队等待 P95 暂定不超过 5 秒，突发容量下暂定不超过 30 秒并触发扩容告警，最终阈值经压测校准。 |

## 4. 安全与隐私需求

| 编号 | 要求 | 验收口径 |
|---|---|---|
| SEC-001 | 产品用户与管理员身份隔离 | Cookie、Session、API 权限和数据表分离 |
| SEC-002 | 项目级隔离 | 每次读取、修改和下载同时校验 user_id 与 project_id |
| SEC-003 | 私有文件 | 原始材料和成果不进入 `public/`，下载使用短期签名地址 |
| SEC-004 | 安全解析 | 验证 magic bytes；不执行宏、不访问外链、限制解压和解析资源 |
| SEC-005 | 提示词注入隔离 | 文件内容永远是数据，不可改变系统指令、工具权限和外部动作 |
| SEC-006 | 日志脱敏 | 默认不记录手机号、文件正文、客户名称、需求、报价和方案正文 |
| SEC-007 | 删除闭环 | 删除覆盖来源、模板、中间文件、项目模型、成果、版本、缓存和索引 |
| SEC-008 | 跨项目零复用 | 禁止跨项目语义缓存、检索或知识复用用户内容 |

## 5. 运营需求

| 编号 | 要求 | 验收口径 |
|---|---|---|
| OPS-001 | 处理链路监控 | 展示接收、解析、建模、生成、渲染、检查、交付各阶段健康度 |
| OPS-002 | 自动恢复 | 重试、备用解析器/模型、缩小范围、局部修复和旧版回退可配置 |
| OPS-003 | 灰度 | 解析器、模型和渲染器变更先跑基准项目，再小流量放量 |
| OPS-004 | 删除积压监控 | 监控删除队列时延、失败和孤儿对象 |
| OPS-005 | 无正文后台 | 运维后台默认不可查看用户正文，不提供人工改稿与交付入口 |
| OPS-006 | 并发容量与公平性 | 按阶段监控活跃 Worker、运行中任务、租约竞争、队列等待 P50/P95/P99、用户级并发和饥饿任务；自动扩缩容且单一用户的大任务不得长期阻塞其他用户。 |

## 6. 暂定参数

以下参数不阻塞设计，但必须通过基准项目校准：

| 编号 | 暂定值 | 校准方式 |
|---|---|---|
| TBD-001 | 未完成临时上传 24 小时 | 观察失败登录、重复上传和存储成本 |
| TBD-002 | 原始材料最后活动后 30 天 | 用户测试与隐私策略评审 |
| TBD-003 | 中间文件成果完成后 7 天 | 重试/修改窗口与成本测试 |
| TBD-004 | 项目模型和成果最后活动后 90 天 | 用户复用行为与删除策略评审 |
| TBD-005 | 项目理解展示 8—12 条核心需求 | 不同规模基准项目可读性测试 |
| TBD-006 | PPT 默认 12—15 页 | 模板兼容与内容密度测试 |
| TBD-007 | 单项目上传安全阈值 | 压缩炸弹、解析耗时、内存和并发压测 |

## 7. 开发追踪规则

- 每个功能任务至少引用一个 `REQ-`，技术任务至少引用一个 `NFR-`、`SEC-` 或 `OPS-`。
- “完成”必须附自动化测试、基准项目结果或渲染证据。
- 任何新增前置步骤都必须证明不会违反 REQ-003。
- 任何文件数量限制都只能是上传安全阈值，不得被描述成交付数量上限。
