# 08 最小完整链路与分阶段实施路线

## 1. 实施原则

- 先证明完整链路，再扩充格式、成果和页面。
- 先做高风险验证，再做大规模 UI 和通用框架。
- 保持现有官网可用，产品域以模块化单体方式加入，不先拆微服务。
- Web 请求只处理交互和短事务；解析、模型、长文档、渲染和删除进入 Worker。
- 支付不进入当前架构和页面，不预埋会绑死流程的订单前置状态。
- 任何阶段的“完成”以基准项目和自动证据为准，不以页面可演示为准。
- ToC 正式开放以多用户并行容量验收为前置条件；单任务 `tick` 只用于本地适配和验证，不作为生产调度架构。

## 2. 目标技术形态

### 2.1 沿用

- Next.js 15 App Router。
- React 18、TypeScript 5、Tailwind CSS 3。
- Drizzle ORM。
- 现有官网页面、CMS 管理域和视觉基础。

### 2.2 新增但不替换官网栈

- PostgreSQL：产品业务和执行数据。
- 私有 S3 兼容对象存储：原始材料、中间文件和成果。
- 独立 Node.js Worker：任务消费、解析、模型调用、渲染和质量检查。
- 数据库任务表：V1 队列、租约、幂等、重试和状态，不先引入复杂队列平台。
- 可水平扩展的 Worker 池：按解析、媒体、正式生成和渲染分配独立并发额度，并实施用户级公平调度。
- 独立产品用户 Session：当前使用用户名密码，和管理员认证隔离；其他登录方式延期。
- Office/PDF 工具链：按高风险验证结果选择。

### 2.3 暂不引入

- Kubernetes、服务网格和多微服务。
- 通用 Agent 框架和工作流可视化编排。
- 跨项目向量知识库。
- 完整在线 Office 编辑器。
- 支付、订单、套餐和计费中心。

## 3. 建议模块边界

```text
app/
  product/                       # 用户页面
  api/product/                   # 产品 API

modules/product/
  auth/                          # 产品用户与 Session
  intake/                        # 需求画布与草稿
  source/                        # 上传、文件、解析和来源块
  project-model/                 # 正式项目模型与关系
  deliverables/                  # 七类成果对象
  change/                        # 锁定、影响、版本和回退
  export/                        # Office/PDF/ZIP
  quality/                       # 四层质量门
  operations/                    # 用量、错误、删除与运行状态

workers/
  runner/                        # 租约、幂等、重试
  tasks/                         # 任务处理器

contracts/
  schemas/                       # JSON Schema
  enums/                         # 状态和关系类型
```

模块通过类型化命令和数据契约协作，禁止页面直接调用模型供应商 SDK。

## 6. 阶段 2：最小完整链路 M0

### 6.1 范围

```text
官网结构化输入
 → 用户名密码登录或注册
 → DOCX/PDF 上传
 → 文件验证与来源块
 → 正式项目模型
 → 需求分析 / 功能清单 / 简版解决方案
 → XLSX / DOCX / PDF
 → 自动质量检查
 → 下载与删除
```

M0 不以聊天为主界面，不要求新建项目和任务。

### 6.2 工作包

| 工作包 | 主要内容 |
|---|---|
| M0-01 产品身份 | 用户名密码、Session、登录前草稿绑定、管理员隔离 |
| M0-02 私有上传 | 签名上传、magic bytes、大小/资源限制、文件状态 |
| M0-03 任务运行器 | 数据库任务表、租约、幂等、重试、状态查询 |
| M0-04 DOCX/PDF 解析 | 统一来源块、页/段/表定位、部分失败 |
| M0-05 正式项目模型 | Schema 校验、来源、假设、冲突和关系 |
| M0-06 三类成果 | 需求、功能和简版方案对象 |
| M0-07 文件输出 | XLSX、DOCX、PDF 与下载签名 |
| M0-08 质量门 | 来源、确定性、语义和文件打开/视觉检查 |
| M0-09 删除 | 立即撤销访问、异步清理和状态 |

### 6.3 退出条件

- BM-01、02、03、04 可从全新用户输入无人值守完成。
- 关键来源定位正确率 100%。
- 需求—功能关系覆盖达到门槛。
- 文件打开率 100%，严重排版问题为 0。
- 删除和跨项目权限测试通过。
- 记录端到端 P50/P95 时间和成本。

## 15. 阶段 11：PPT 视觉优先复原 M9（主流程完成后）

### 工作

- 锁定来自统一项目模型的逐页正文、数字、表格、引用和备注，生成内容清单与校验摘要。
- 以整套 Deck 的统一视觉方向生成页面参考图，再按共享设计令牌复原为语义 HTML。
- 将 HTML 中的文字、形状、表格和图表映射为 PPT 原生可编辑对象；装饰性视觉作为独立图片资产。
- 将 PPTX 回渲染为图片，与 HTML 和视觉参考进行自动比对，并验证全套格式一致性。
- 建立视觉资产缓存和局部重渲染机制，避免内容小改时重复消耗图像生成成本。

### 退出条件

- 必需正文、关键数字、表格单元格、引用和演讲备注的内容核对通过率为 100%。
- 全套页面使用同一字体、色板、网格、间距、图标和图片处理规则，无逐页风格漂移。
- 无文字截断、对象重叠、越过安全区、缺失字体和不可打开文件。
- 文字、基础图形、表格和支持范围内的图表可在 PowerPoint 中独立编辑。
- PPTX 回渲染结果通过可配置的视觉差异门槛；失败版本不得替换上一可用发布版。
