# 11 延期集成与技术债务

## AUTH-DEBT-001 多方式登录

- 当前决定：产品用户只使用用户名和密码，产品 Session 与管理员认证完全隔离。
- 延期内容：手机号验证码、邮箱验证、企业 SSO、微信/其他第三方身份、支付账号联动。
- 原因：先跑通无需人工处理的完整生成和交付流程，避免在身份供应商上提前投入。
- 未来要求：新增登录方式只能关联现有 `product_user_id`，不得把管理员或支付身份表直接合并为产品用户表；账号合并需独立审计和冲突处理。
- 当前风险：密码找回尚未实现，正式对外开放前必须选择至少一种可自动完成的找回或重置方式。

## PAYMENT-DEBT-001 支付与权益

- 当前决定：完整流程跑通和无人值守指标达标前不接入支付。
- 延期内容：套餐、订单、支付回调、发票、退款、权益和用量结算。
- 未来要求：支付只授予产品权益，不成为产品身份主键；失败或退款不能导致用户数据不可访问或无法删除。

## DATA-DEBT-001 产品数据库迁移

- 当前决定：为尽快跑通本地完整链路，产品身份暂存独立 SQLite `product.db`，不与 CMS 数据库共表。
- 正式要求：进入外部灰度前迁移至 PostgreSQL，补齐数据库级租户约束、迁移脚本、连接池、备份和高可用策略。
- 迁移边界：产品用户 UUID、规范化用户名和密码哈希保持稳定；不得通过导出明文密码迁移。

## STORAGE-DEBT-001 私有对象存储

- 当前决定：完整链路开发阶段使用产品专用本地私有目录，按用户、方案和文件 UUID 隔离，文件不进入 `public`。
- 正式要求：进入外部灰度前迁移至私有对象存储，补齐短期上传凭证、服务端加密、生命周期、恶意文件扫描、备份与删除审计。
- 迁移边界：保持 `storage_key` 抽象、文件 UUID、SHA-256、真实格式检测和租户授权规则不变；不得为了对象存储迁移改变用户的填写、登录和自动开始流程。

## RUNTIME-DEBT-001 独立处理 Worker

- 当前决定：已经提供独立长驻 `scripts/product-worker.mjs`，通过内部 tick API 驱动解析、媒体、正式生成、渲染、删除、运行快照和存储维护，并持久化租约、重试、错误码和心跳。
- 正式要求：进入并发灰度前将当前 SQLite/HTTP 调度适配层迁移到可水平扩展的任务队列与 Worker 运行环境，完成多主机租约、死信、限流、容量和监控验收。
- 迁移边界：保持处理记录、材料块、初步理解和进度接口不变；同一方案与输入不得重复产生材料块。

## RUNTIME-DEBT-002 ToC 并行执行与容量弹性（开放前阻断项）

- 产品定位：面向 ToC 开放，不能依赖一个全局 Worker 逐个处理用户任务，也不能让长文档或大附件占住全部执行能力。
- 并行边界：不同用户之间并行；同一用户的不同方案并行；同一方案中无依赖的媒体块、章节准备和成果渲染可以并行；存在明确数据依赖的步骤继续按 DAG 顺序执行。
- 正式要求：任务队列支持多 Worker 并发领取、原子租约、心跳续租、幂等提交、超时回收、指数退避、死信和水平扩缩容。当前 `tick?limit=` 仅作为本地与部署适配接口，不代表生产并发上限。
- 公平性：按用户和任务类型设置可配置并发配额及加权公平调度，避免单个超大项目导致其他用户饥饿；配额用于公平和供应商保护，不在用户流程中增加“新建任务”等前置操作。
- 供应商保护：分别管理 OCR、低成本模型、高质量模型和渲染器的并发与速率限制；达到供应商上限时优先扩展可验证备用能力，不能静默降级正式交付质量。
- 容量目标：正常容量下任务排队等待 P95 暂定不超过 5 秒；突发容量下 P95 暂定不超过 30 秒并自动扩容。正式开放前必须用多用户混合材料压测校准，不以单用户演示结果代替。
- 验收阻断：必须完成并发正确性、租约竞争、重复消费、Worker 崩溃恢复、供应商限流、热点用户公平性和扩缩容测试，且无跨用户数据混用、重复生成或重复成本记录。

## MODEL-CONFIG-001 模型槽位与密钥

- 免费初步分析：`PRODUCT_FREE_MODEL_PROVIDER` 与 `PRODUCT_FREE_MODEL`，默认低成本槽位为 `openai` / `gpt-5.4-nano`；无密钥或调用失败时明确使用 `deterministic_fallback`，不得冒充模型结果。
- 正式分析：使用独立的 `PRODUCT_FORMAL_MODEL_PROVIDER` 与 `PRODUCT_FORMAL_MODEL`，不得因为免费槽位成功而自动复用低成本模型生成正式交付内容。
- 当前要求：模型调用记录供应商、模型、输入/输出 Token 和可配置成本估算；密钥只通过服务端环境变量提供，不写入数据库或前端。
- 交接方式：复制仓库根目录的 `.env.product.example` 到本地 `.env.local` 或部署密钥存储并填写真实值。产品 Worker、`config:check` 和 `provider:check` 都会读取 `.env.local`，部署环境中已注入的变量默认优先；若桌面环境注入了无关密钥，本地 `.env.local` 可显式设为 `PRODUCT_ENV_FILE_OVERRIDE=true`。获得 Key 后，先运行 `npm run config:check` 完成纯本地配置预检；只有获得明确授权后，才运行会向供应商发送最小请求的 `npm run provider:check`。
- 夜间价差：启用 `PRODUCT_MODEL_EXECUTION_WINDOW_ENABLED=true` 后，初步理解、OCR、视觉和正式文本模型调用只在 `PRODUCT_MODEL_EXECUTION_TIMEZONE` 的 `[PRODUCT_MODEL_EXECUTION_START_HOUR, PRODUCT_MODEL_EXECUTION_END_HOUR)` 内执行；默认是 `Asia/Shanghai` 的 00:00–05:59:59。校验位于 Worker 消费路径内，手动 tick、重试和故障恢复都不能绕过；窗口外 OCR、视觉、正式文本任务保留排队状态且不计入失败重试，初步理解明确记录为 `night_window_deterministic_fallback`，不会冒充模型结果。

## PPT-VISUAL-001 视觉优先的可编辑 PPT

- 当前决定：已完成现有 PPT 生成器的第一阶段原生图形化增强；继续优先完成主流程验收，不提前引入图像模型和 HTML 复原链路。
- 已完成：按章节类型生成内容卡片、实施时间线、风险矩阵和工作量指标卡片，所有对象保持 PPT 原生可编辑。
- 延期内容：使用图像生成确定高质量视觉方向，复原为语义 HTML，再转换为原生可编辑 PPTX。
- 内容边界：生成图不得成为正文事实源，不得通过 OCR 回填文字、数字、表格或引用；所有交付内容必须来自统一项目模型。
- 质量边界：内容不得丢失，全套格式必须统一，支持对象必须可编辑，转换失败不得发布不完整成果。
- 详细设计与验收标准见 `12-ppt-visual-first-rendering.md`。
