## 已验证能力

- 能从跨格式资料中检出范围、角色权限、数据质量和冲突证据等关键事实。
- Word 表格可回放至表号和行号；PDF 可回放至页码和块号；Excel 可回放至工作表和单元格范围；PPTX 可回放至页码、形状序号和归一化坐标。
- 用户提供的 PPTX 模板可标记为 `template_style`，不会与项目正文混入同一事实语料。
- Excel 日期同时保留原始序列、数字格式和 ISO 显示值；合并区域仅保留锚点，避免重复文本进入模型上下文。
- Excel 公式及原生图表的数据范围保持可追溯，图表无需先截图再交给模型猜测。
- 无文本层的扫描页不会被丢弃，而是保留全页媒体引用并标记 `ocr_required`。
- 当前基准的 69 条媒体路由中：67 条直接使用确定性文本、1 条进入标准 OCR、1 条 PPTX 图片进入低成本视觉模型；初始阶段没有高质量视觉模型调用。
- OCR 结果通过供应商无关契约重新生成 7 个来源块；6 个高置信度块直接进入确定性文本处理，仅 1 个低置信度冲突块升级至低成本视觉复核。
- 权限冲突章节的上下文包在 900 token 上限下使用 808 token，保留 90 token 安全余量；包含 13 个去重证据块、稳定项目主干、锁定决策和上一章节摘要。
- 扫描副本声明来源派生关系；当原生 PDF 同时存在时，OCR 副本不会重复进入模型上下文。
- 长文档方案按 5 个依赖章节维护状态账本；支持中断恢复、单章质量门和依赖级局部失效，账本只保存摘要与哈希，不重复保存正文。
- 章节质量门覆盖引用完整性、上下文越界、范围承诺、冲突遗漏、跨章重复和术语一致性；错误自动阻断，警告进入自动返修提示。
- 免费分析固定使用经济型文本槽位，正式分析、章节生成、修改和最终质量审查固定使用高质量槽位；预算不足不允许静默降级。
- 完整成果包的 7 类成果、17 个格式文件复用 9 个语义模块，其中 7 个模块调用模型、2 个模块确定性计算；加权成本由逐格式重复生成的 1,022,000 降至 127,000，避免 895,000（87.57%）重复成本。
- DOCX、PDF、PPTX、XLSX 等输出均为确定性渲染任务；增加一种已有成果的输出格式只增加渲染任务，不增加模型调用或语义生成 token。
- 完整成果计划展开为 35 个可恢复节点：9 个内容节点、9 个独立质量门和 17 个确定性渲染节点。失败节点可自动重试；上游变化只失效依赖它的质量门和成果格式，不重跑无关内容。
- 内容版本与模板/渲染版本已分离：更换企业模板只产生新渲染版本且模型调用为 0；客户成果包自动排除内部文件，禁止跨内容版本混装，并支持候选发布失败不影响旧版及活动版本指针回滚。
- R/C/S/P 修改已进入显式影响图：BM-01 的模板变更和日单价变更模型调用均为 0；单条需求修改只覆盖其 16 个下游对象；核心方向变化才重建项目模型。传播遇到锁定对象会产生冲突并停止，不修改锁定对象及其下游。
- 任务运行时已验证幂等提交、依赖阻塞、Worker 租约超时回收、指数退避和预算恢复；模拟 Worker 崩溃、模型超时和正式模型预算延迟后均能自动续跑，任务链不包含人工处理分支。
- 用户进度已从内部 35 节点聚合为理解信息、形成内容、一致性检查、生成文件、自动恢复和完成六个阶段；单项成果完成即可查看和下载，自动恢复不要求用户操作，局部变更不隐藏无关的可用成果。
- 登录前需求画布已支持一次性凭证绑定和幂等恢复：登录失败不丢字段或文件选择，登录成功后自动建立私有方案归属并开始理解；文件内容仅在登录后上传到私有 Key，跨用户接管被拒绝。
- 上传预检按真实字节识别格式，BM-01 五个文件全部通过；扩展名伪装、宏文档、加密 PDF 和高压缩比文件在解析前被隔离。无效企业模板自动使用默认模板，单文件失败不阻断其他有效内容。
- 私有文件访问已绑定用户、方案和文件三重归属；跨用户、路径穿越、签名篡改、过期链接和超长有效期全部拒绝。方案删除先撤销访问，旧下载链接立即失效，对象存储清理可异步完成。
- 删除链已验证同步撤权、墓碑、对象/派生数据清理、日志匿名化、备份墓碑和最终缺失检查；模拟对象存储故障后可自动续跑，备份恢复不会复活已删方案，账号注销不影响其他用户。
- 无人化监控已覆盖成功率、完整成果交付率、P50/P95、积压、重试、成本和供应商健康；异常自动暂停灰度、扩容或切已验证备用。成本异常只限制免费分析并延迟新正式任务，正式任务静默降级数固定为 0。
- 产品接口已统一到 `/api/product/*`，与管理员认证和 CMS 公共图片上传隔离；首个需求最低条件校验接口已实现。接口目录禁止客户端提交 `userId`，也不存在新建项目、创建任务或选择模型前置接口。
- 官网首页已接入真实输入入口，用户可填写用途、客户与用户、问题描述、产品形态、约束并选择三类附件；可见标题使用“说清楚你要解决的问题，剩下的交给我们”，不暴露“需求画布”等内部术语。桌面、390px 手机、最低条件校验、附件选择和登录层浏览器验收通过。
- 产品身份已调整为用户名密码注册/登录，使用独立 `product.db`、独立签名密钥和 HttpOnly 产品 Session，不复用管理员账号。手机号、第三方登录、密码找回和支付身份联动已记录为延期技术债务。
- 同一文件内容、解析器版本和定位条件下，UUIDv5 来源块 ID 可重复生成。
- 171 个来源块全部通过 JSON Schema Draft 2020-12 和 UUID 格式校验，68 个 PDF 块全部带归一化坐标框。

## 已知边界和下一步

1. DOCX 的 OOXML 结构不包含可靠页码。下一步用 LibreOffice/PDF 渲染结果补齐视觉页码映射。
2. 扫描 PDF 已进入 OCR/视觉成本路由并完成结果回写验证；实际 OCR 引擎需在部署环境接入，低置信度结果按规则自动升级，无人工节点。
3. Excel 日期、合并单元格和原生图表已恢复；下一步补充数据验证、条件格式和透视表元数据。
4. PPTX 已进入结构解析通道；下一步继续恢复母版、版式继承、主题色和字体映射。图片语义仍需视觉模型处理。
5. 解析完成后才进入模型路由：便宜模型负责免费分析和初筛，高质量模型负责正式分析与最终内容生成。

当前 SPIKE 证明的是“资料可确定性拆解和追溯”，不代表已经完成生产级多格式理解。
