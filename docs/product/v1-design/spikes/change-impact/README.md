# SPIKE-04A：R/C/S/P 修改影响计算

- R：模板、Logo、颜色和版式变化，只生成渲染任务，模型调用为 0。
- C：税率、日单价和计算参数变化，只执行确定性计算、引用检查和相关渲染，模型调用为 0。
- S：需求、功能、部署或计划变化，沿显式关系图局部生成、重算、检查和渲染。
- P：客户、产品方向或核心范围变化，建立新的正式项目模型候选版本，旧发布版继续可用。

传播遇到锁定对象即停止并生成冲突，不绕过锁定继续修改。每个受影响对象保存完整原因路径，可直接用于界面的“为什么受影响”说明和执行状态机失效范围。

## 工程进度

- 已实现供应商无关的 R/C/S/P 影响规划器：根据调用方提供的节点、边和锁定节点生成确定性动作、原因路径、冲突及未受影响对象。
- 已覆盖模板重渲染、参数重算、语义修改、项目模型重建、锁定阻断、无效目标和环路安全；单元测试不访问模型或数据库。
- 项目模型候选版本、实体和关系已落库；支持激活、回滚、项目/模型锁定、状态读取与影响计划留档，并以项目所有权约束 API。隔离 SQLite 测试覆盖版本链、关系、锁定冲突、计划留档与访问隔离。
- V1 传播规则：S 仅沿 `satisfies`、`implemented_by`、`depends_on`、`derived_from` 的 `from → to` 方向传播；P 从 `PROJECT_MODEL` 节点重建模型，并检查所有模型实体；`conflicts_with` 作为单独冲突提示返回，不传播；其余关系类型默认不传播。遇到锁定实体即阻断该路径。
- 存储图适配器与 `POST /api/product/solutions/:id/project-model/impact` 预览接口已接入：从活动快照读取实体/关系并留存 S/P 影响计划。R 已接入模板与品牌替换的确定性重渲染；C 已接入报价参数覆盖 API 与成果页编辑器，人天/系数变化只失效估算表和报价表，单价/税率/折扣等报价项只失效报价表。C 不调用模型，旧 Word/PPT 与无关交付保持可用；R/C 返回实际失效成果范围，不使用项目实体关系猜测影响集。
- `POST /api/product/solutions/:id/project-model/impact/:planId/accept` 已实现计划确认：拒绝有锁定冲突的计划、旧活动快照上的过期计划和重复确认；只将状态改为 `accepted`，不会自行触发模型或文档生成。
- 正式章节映射 V1 已实现并进入章节生成上下文：目标与背景→项目背景；范围/用户/约束→范围与用户；场景/需求/功能/Agent 能力→需求；功能/集成/数据实体/约束→解决方案；需求/功能/集成/数据实体→工作量依据；场景/功能/集成/约束→实施计划；排除范围/约束/假设/冲突/集成→风险。术语属于跨章节公共依据；P 变更覆盖全部七章。活动模型上下文只传递本章实体摘要、关系、术语和项目身份，不传内部 UUID 与材料 sourceRef。
- 正式章节的连续性摘要与结构化条目现只读取本章之前已验证章节，避免后续章节旧摘要反向污染前序章节重建。影响预览同时返回 `sectionTargets`，说明哪些正式章节会因哪些模型实体进入候选重建。
- `POST /api/product/solutions/:id/project-model/impact/:planId/execute` 已接入正式章节失效：要求提交以计划基线为父版本的候选模型；S 变更会验证候选只改动计划覆盖且未锁定的实体/关系；随后在一个事务中激活候选、仅将映射章节置为 pending、将旧交付标为 superseded 并启动正式分析队列。HTTP 请求本身不调用模型；后台正式章节 worker 生成完全部必要章节后将执行计划标记 completed，重试耗尽时标记 failed，自动修复后恢复执行状态。候选版本与基线不符、实体越界或计划过期时整体回滚。
- `POST /api/product/solutions/:id/project-model/entities/:entityKey/revision` 已提供按稳定实体键创建候选的编辑接口：仅开放实体类型允许的字段，校验字段类型，并拒绝模型锁/用户锁实体；生成的候选从活动版本派生，可继续走“预览→确认→执行”链路。自由文本不会被静默猜测成某个实体的局部修改；如需整体吸收新增事实，应使用修订候选生成入口，再人工核对候选。
- 方案进度页已接入项目模型修订面板：读取活动版本与锁定状态，逐条选择、编辑实体，展示章节影响和冲突，并通过明确确认启动局部重建。首次建模时，可调用 Responses API 将已确认事实整理为候选；每项输出必须引用已知事实，服务端将事实引用转换为材料块引用并校验，不可追溯的内容直接拒绝。候选模型可在页面查看目标、范围、需求摘要，只有用户确认后才会激活；若已有正式文档，激活会让全部章节失效并进入完整重建队列。
- 活动项目模型修订现可将一条或多条仍有效的用户确认事实显式关联到选定实体；服务端校验引用 ID、角色、重复项，并验证事实归属当前用户和方案、材料块引用属于当前方案。关联来源与实体文字作为同一个候选保存，继续走影响预览及人工执行确认；关联事实本身不会自动改写实体文字，也不会自动激活模型。隔离状态测试覆盖有效事实、撤销/不存在事实、跨用户事实和非法来源 ID。
- 初始候选会留存在版本表中，刷新后仍可继续审阅；模型调用记录单独标注 `project_model_draft`。隔离 SQLite 测试通过 mock Responses 响应验证严格结构化请求、来源映射、候选存储和“生成不自动激活”。项目模型候选列表只对方案所有者开放。
- 活动模型存在时，方案进度页可根据最新统一知识重新生成 `project_model_revision_draft` 候选；新候选以当前活动版本为父版本，仍不自动激活，用户确认启用后才进入全量正式章节重建。隔离测试覆盖活动版本保留、候选落库和调用目的区分。
- 候选审阅支持显式放弃候选；放弃只将候选标为 `rejected`，不改变活动模型、正式章节或交付成果，并拒绝重复处理已结束的候选。
- 活动版本历史现在可从修订面板查看；恢复历史模型需要二次确认。恢复通过同一原子激活事务执行，正式文档存在时全量失效并重建，不删除旧交付文件；隔离测试覆盖恢复后活动指针和七章失效行为。
- 报价与估算参数支持按稳定结构化条目编号覆盖：校验税率/折扣率、系数、人天、金额和有效期的范围，方案所有权隔离，写入项目事件；参数哈希纳入相应成果内容版本，变更以渲染队列生成新文件，原文件进入版本历史。报价 PDF 与 Excel 共用结构化估算项及用户参数；PDF 展示基准人天、五类系数链和调整后人天，并明确计算顺序。缺少基准人天、任一系数或价格/税率/折扣时均标记待补，不推定为 0 或 1；两种格式采用相同的报价齐备规则，并明确标记这不是完整报价。mock SQLite 测试检查影响范围、Excel 公式和 PDF 可读文件头，无模型调用。
- 该执行路径已用隔离 SQLite 验证“只重置映射章节、保留无关章节”和重复执行保护。用户事实/新材料的现有入口仍执行全量理解失效，因为自由文本尚未映射到模型实体；不根据自由文本猜测或静默自动应用新版本。文档内容质量的端到端验证仍待后续提供模板参考后统一进行，当前未跑基准测试，也没有发起真实模型调用。
